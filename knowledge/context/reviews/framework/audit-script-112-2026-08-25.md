## Findings

### WARNING W1: `.gitignore` prev-line semantics changed (rule #4 marker source)
`scripts/path_reference_audit.sh` main loop. Old code `continue`d past
non-comment `.gitignore` lines BEFORE the `prev_line="${line}"` update, so
for a `.gitignore` comment line, `prev_line` was the last *comment* line.
New code uses the literal previous line (`file_lines[lineno-2]`), which can
be an ignore *pattern*. Proven divergence (Probe B): pattern line ending in
`example` followed by a comment citing a dead path -> old reports the dead
ref, new suppresses it via the example-marker heuristic. Unreachable on the
current `.gitignore` (clean-tree run is byte-identical), and the new
behavior arguably matches rule #4's documented "line just above it" intent,
but it is an unclaimed behavior change that can *swallow* a dead reference.
Smallest fix if strict identity is wanted: in the `.gitignore` branch,
derive `prev_line` from the last preceding comment line instead of
`lineno-2`. Acceptable alternative: document the delta in the script header.

### WARNING W2: final line without trailing newline is now audited
Old `while IFS= read -r line` silently dropped a file's last line when it
lacked a trailing newline (read returns nonzero); `mapfile` keeps it.
Proven divergence (Probe B): dead ref on an unterminated final line of an
agent file -> old silent, new reports it (exit 2). Every current corpus
file is newline-terminated, so clean-tree identity holds. This is a latent
bug *fix* (the audit now sees a line it used to miss), but it is unclaimed;
worth one line in the script header or PR description so a future
"the audit newly flags X" is not mistaken for a regression.

### NIT N1: lesson overstates "byte-identical"
`knowledge/lessons/no-subprocess-in-per-item-shell-loops.md` and its INDEX
row state byte-identical output unqualified. True for every state the
author tested and every realistic state I tested, but W1/W2 are real
divergences on synthetic inputs. A one-clause caveat ("on the current
corpus and injected-dead states") would make the lesson exact. Lesson file
otherwise conforms to knowledge/lessons/ conventions (kebab name, Date/Cost
header, INDEX row added, newest-first).

## If shipped as-is
