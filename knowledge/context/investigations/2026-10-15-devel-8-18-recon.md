## 3. Unsigned pak policy

**The toggle does not appear to exist on 8.18.7. Every probe that worked on 9.1.1 came back absent.**
This is a read-only conclusion; the definitive proof is an upload, which is a write (see end).

| Probe (9.1.1 behavior) | 8.18.7 result |
|---|---|
| `POST /ui/solution.action mainAction=getIntegrations` returns `isUnsignedPakInstallationAllowed` | Response keys are only availableMPs, pakCategories, totalIntegrationsCount, installedMPs, installationState. **Key absent** |
| `POST /admin/clusterManagement.action mainAction=getUPIStatus` returns `{"status":"true/false"}` | HTTP 200, **empty body** (no such handler behavior) |
| `POST /admin/clusterManagement.action mainAction=isPakInstalling` includes the flag | Returns `{"isPakInstalling":false,"isPakUninstallActive":false,"isNewCluster":false}`, **no flag** |
| `GET /casa/upgrade/cluster/pak/allow_unsigned_pak` and `/slice/` variant | Both **404** (admin Basic auth worked on other CaSA paths, so this is a missing route, not auth) |
| Admin UI bundle keys `unsignedPakInstallation.*` | **None.** The only unsigned strings are `solutions.signingstatus.NotSigned` = "The PAK file is unsigned." and `solutions.notsigned.confirmation` = "You have selected a software update that is unsigned. Are you sure you want to install this software update?" |

Reading: on 8.18 an unsigned pak triggers a warn-and-confirm in the UI, with no cluster-wide
gate. That matches the pre-9.0 behavior and means `unsigned_pak_installation.not.allowed`
should not occur here (INFERRED). The installer's preflight must treat a missing
`isUnsignedPakInstallationAllowed` key as "no gate", not as false, or it will wrongly abort on 8.18.
Not checked: the product-UI message bundle (`getMessageBundle`) for `ignoreSignatureChecking`
strings, and the actual `ignoreSignatureChecking` handling on upload.
